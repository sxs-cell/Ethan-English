## 三、内容规划

### 3.1 内容栏目与更新策略

| 栏目 | 内容类型 | 建议更新频率 | 运营要点 |
|------|---------|------------|---------|
| 范文库 | 真题范文、模板示范、学员佳作 | 每周 2–3 篇原创解析 | 每篇标注"结构拆解 + 亮点句型"，避免陈旧 |
| 词汇库 | 主题词、高频短语、熟词僻义 | 每月批量补充 | 结合当年真题主题词迭代 |
| 写作技巧 | 方法论长文（如"5 步写出高分议论文"） | 每周 1 篇 | 案例式拆解范文结构 |
| 真题库 | 历年题目 + 审题分析 | 每年 12 月更新当年真题 | 附"审题 + 立意 + 模板适配" |
| 批改 | 写作挑战、读者投稿点评 | 每周 1 次互动 | 精选投稿做公开点评，形成 UGC 案例 |

### 3.2 内容差异化四象限（对应你规划的差异化方向）

- **技巧类**："5 步写出高分议论文" → 已有三段式 + 七方案可拆成系列文章
- **案例类**："拆解范文结构" → 用"填空式模板"降低门槛，标注可替换主题词
- **资源类**：模板、高频短语库 → 已落地（范文/词汇/资源下载）
- **互动类**：写作挑战、投稿点评 → 批改页 + 未来接入社群

## 五、技术选型落地（对齐你的第一阶段）

### 5.1 当前形态（静态原型）
- **技术栈**：HTML + CSS + JS（原生，零依赖）
- **特点**：可本地双击打开或任意静态托管（GitHub Pages / Vercel / OSS + CDN）直接部署
- **适用**：MVP 验证、内容快速上线、SEO 友好（纯静态 HTML 最易被搜索引擎收录）

### 5.2 正式上线建议（分阶段演进）

| 阶段 | 技术方案 | 适用场景 |
|------|---------|---------|
| **阶段一（当前）** | 纯静态站 + 托管 | 内容型 MVP，验证内容吸引力 |
| **阶段二** | 静态站 + Headless CMS（如 WordPress/Strapi/Drupal） | 内容多、需多人协作更新时 |
| **阶段三** | 加数据库（MongoDB）+ Redis 缓存 + 后端 API | 承载 UGC 作文、批改记录、用户体系 |
| **阶段四** | 接入 LLM 批改 / Grammarly API + 支付（会员） | 变现与智能化 |

> 关键判断：**先纯静态跑内容，等有真实 UGC（作文投稿）和用户体系需求，再上数据库和 CMS**。你规划里提到的 MongoDB + Redis，适合承载"大量外刊 PDF 等非结构化数据 + 高频批改请求缓存"，属于阶段三的事，不建议 MVP 阶段就上。

## 八、下一步建议

1. **立即可用**：`kaoyan-site/` 目录双击 `index.html` 或部署到任意静态托管即可上线。
2. **内容补全**：把范文库从 6 篇扩到真题范文（每周 2–3 篇），词汇库持续补词。
3. **功能迭代**：优先做「批改历史记录 + 打卡勋章」两个留存功能，再接入真实 AI 批改。
4. **数据埋点**：上线后加访问统计，用数据验证哪个栏目最受欢迎，再决定上数据库/CMS。
